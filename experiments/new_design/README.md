# 新设计独立实验版

本目录实现了[新设计](../../docs/research/new_design.md)的主干。这里的 [`kernel.asc`](kernel.asc) 是与根目录可靠版本分离的单文件 CANNJudge 候选，使用相同 `run_kernel` 接口。首次提交 `403810` 为 15 项全 0 用时 Wrong Answer；恢复可靠版工作区初始化后达到 14/15 Pass。进一步将小 M/N 形状切换到整 batch 模式，并让该模式使用可靠版的 M/N 消费实现，提交 `404933` 达到 **15/15 Pass**。当前文件与 `404933` 的线上源码哈希一致；根目录可靠版仍未替换。提交工具可直接用 `--file experiments/new_design/kernel.asc` 读取本文件，无需覆盖根目录源码。

## 已实现

- 模式 A：每个 block 拥有完整 batch；模式 B：按 M tile 并行并写入对齐的部分和；模式 C：按连续 M×N 分区并行，写逐行部分最大值。部分结果只经过一次全局同步，再由每个 batch 的固定 owner 合并。`B` 大于 block 数时 owner 仍循环覆盖所有 batch。
- 模式 A 使用可靠版已验证的 M/N 消费实现；模式 B/C 共用实验版的 C tile 行最大值消费逻辑。`callTiles` 控制一次 MatMul 调用的 N tile 数量，与 N 分区数独立；`kMaxCallTiles`、`kPreferAsyncC` 是受控对比开关。`K%16!=0` 使用单 N tile 同步兼容路径，保留窄条件 FP16 行 GEMV。Host 对 `M<=32、N<=128` 的小形状选择模式 A。
- Host 按 tiler 实际返回的 baseM/baseN 规划任务与缓冲。当前候选恢复可靠版方式，为每个 block 分配完整 N tile 范围的异步暂存，并始终初始化 MatMul workspace；这是排除 0 用时失败后的保守实现，尚未重新验证按调用段长缩小暂存的方案。M 部分和各占 32 字节槽位。

## 验证与限制

2026-09-30后续设备套件发现本文件的N尾块输出步长问题，独立修复在`experiments/cannlab_tuning/`。下面保留早期最小冒烟和历史线上结果的范围；最终交接以[HANDOFF](../../HANDOFF.md)为准，不能把最小路径成功当作完整设备通过。

[`tests/new_design_test.py`](../../tests/new_design_test.py) 的 CPU 模型检查了公式、任务与 owner 覆盖、分段覆盖、全负输入、尾块、FP16/BF16 量化和四种存储布局。它**不**编译或运行本目录的 Ascend C 源码，也不验证设备内存可见性或性能。线上 `404933` 的 15 个测试点均通过；一次线上通过不等于已获得独立 NPU 设备日志或性能剖析。

2026-09-30，CANNLab 最小设备冒烟检查中，可靠版与本候选均成功编译、启动，并在 FP16 `B=1,M=1,N=1,K=32`、非转置布局上得到 `-0.25`，与 CPU 参考完全一致。该结果只验证最小路径的设备可执行性，不覆盖 BF16、其它布局、尾块、大矩阵调度或线上 15 个 case；后续远端套件继续扩展这些边界。

在替换可靠版本前，应比较线上 15 项性能并取得目标 NPU 的实际 tiling、资源和同步证据。设计第 7.2、7.3 节的 Split-K 和输出方向交换仍是后续研究候选，本实验版没有实现。根目录 [`main.asc`](../../main.asc) 默认包含根目录 `kernel.asc`；其 CMake 构建不会自动编译这里的候选。

线上提交时先按[工具说明](../../tools/README.md)准备登录状态、检查候选哈希，再显式选择本文件；线上提交会消耗次数。

主任务已在设备验证两份候选的 103 个固定用例；A 整理首版另有八布局、24 次 profiling 的精度及单计算 kernel 检查通过。上述记录说明这些输入的执行结果，不代表所有可能边界全面通过。

## 登录恢复后的执行规则

1. 在 CANNJudge 保存更新后的登录状态到本机忽略路径，再执行 `check`，确认登录及当前提交未运行。
2. 再次 `preview --file` 核对上述哈希；若源码变化，则重新确认记录和设备验证范围，避免串版本。
3. 先提交第一份，按返回的具体 object ID 读取结果，并检查服务端 `kernel.asc` 的 LF 字节数和 SHA-256。
4. 第一份评测终止后才提交第二份，并独立归档结果。不得以“最新提交”代替具体 ID 的归属检查。
5. 每份记录 15 个 case 的状态、时间、精度及 `best_time`。只有全部精度通过时，按项目已核对的官方公式 `mean(100 / (1 + log(t / T) / log(1.5)))` 重算得分，并注明这是根据详情重算还是排行榜实得。

公式来源为 [赛题说明](../spec/problem_official.md)；历史的线上公式核对与排行榜一致性证据见 [历史记录 8.13](memory.md)。最终两份线上结果已取得，分数见开头；没有根据case编号推测隐藏形状。

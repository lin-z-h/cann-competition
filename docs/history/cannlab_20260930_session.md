## 第一轮与第二轮性能对比

形状均为 `B=1,M=4096,N=256,K=64`。FP16 用 t00，BF16 用 t10。每格为 msprof 三次独立进程运行的 kernel 时间中位数，括号内是最小–最大值，单位 us。每次均通过独立参考精度检查，且只有一个计算 kernel。以下结果只适用于这些形状，不据此推断线上总分。

| 版本/参数 | FP16 t00 | BF16 t10 |
| --- | --- | --- |
| 修复候选、最多 4 N tile/调用 | 45.379（45.259–47.979） | 122.857（121.437–123.057） |
| 修复候选、单 N tile/调用 | 51.239（50.339–51.939） | 125.958（123.958–133.737） |
| 历史可靠版，源码未改 | 40.199（39.240–43.379） | 126.917（117.938–129.357） |
| 修复候选、baseM=64 | 50.959（49.159–53.139） | 146.437（145.097–146.977） |
| 修复候选、对齐 M 分条复用原消费者 | 44.659（44.300–44.979） | 120.338（120.078–124.677） |

- 第一步保留多 tile 分段：单 tile FP16 中位数慢约 12.9%，BF16 慢约 2.5%，BF16 差距较小。
- 管线指标中，BF16 t10 的 aic_mte2_ratio 中位数为 `0.569`，aic_mac_ratio `0.005`、aic_scalar_ratio `0.952`；FP16 t00 对应约 `0.169`、`0.015`、`0.886`。这些是重叠管线活动比例，不能相加为端到端时间。
- 补充 Memory 采集：BF16 kernel `120.238 us`，报告 aic_main_mem_read_bw `0.083 GB/s`。高 MTE2 活动比例不等于 HBM 带宽饱和；当前测量更支持关注碎片搬运、布局和控制开销，尚未确定唯一根因。
- 第二步测试 baseM=64：两类型均变慢，不采用。该版本大 M 的 8 个随机用例重复两轮通过，另 8 个大 M/N 尾块随机用例通过。
- 第三步测试对齐消费快路径：在模式 B、M/N/K 对齐且整段 N 可在一次调用内完成时，复用已经验证的原消费者，减少分段 bookkeeping 与一次归约 buffer 的额外分配。其它路径继续使用尾块修复。该版本完整 87/87 设备回归通过，首次性能差距仅约 1.6%/2.1%，进一步进行交替采样后再决定是否采用。

原始 profiler 汇总、CSV、设备精度日志已下载到本地忽略路径 `build/remote-evidence/session-20260930/`，远端仍保留 `build/profile-*` 数据。Profiler 汇总还保存每个被测二进制的 SHA-256，避免源码或构建参数变化后误认旧数据。

| 类型 | 修复基线中位数（范围）us | 对齐快路径中位数（范围）us |
| --- | --- | --- |
| FP16 t00 | 46.059（43.599–47.279） | 43.899（43.759–47.219） |
| BF16 t10 | 120.978（119.077–126.478） | 120.158（117.397–128.738） |

FP16 中位数改善约 4.69%，但个别对照对存在反向波动；不能声称每次执行都会更快。BF16 中位数改善仅约 0.68%，不足以确认稳定收益。最终候选仅对 FP16 启用对齐快路径，BF16 保留修复基线。默认最多 4 个 N tile/调用，baseM 使用原选择。

四 N tile、较大 K 的补充边界 `M=2048,N=512,K=256`，两类型 × 四布局共 8 个随机用例，在快路径版本重复两轮通过。统一入口的最终套件现包含 23 个原始用例 + 9 个随机形状 × 两类型 × 四布局，共 95 个设备用例。
